# 8cli against n8n 2.40.5

Validation of every 8cli command against n8n 2.40.5, the newest release, and what changed since
2.25.7 (the previous e2e pin). Tracking issue: [#32](https://github.com/qodeca/8cli/issues/32).

**Result:** 8cli works on n8n 2.40.5. No command broke because of the upgrade. Two things changed
in n8n that users will notice – deleting a published workflow is now refused, and activate /
deactivate now use deprecated endpoints. The validation also found six defects that already
existed on 2.25.7. Every defect has its own issue (below).

## How it was checked

| Item         | Value                                                                                                     |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| n8n          | `n8nio/n8n:2.40.5` (digest pinned in `test/e2e/setup/global.ts`), free Community edition, no license      |
| Local runs   | `npm run n8n:local -- start` (see `docs/runbooks/local-n8n.md`), SQLite                                   |
| 8cli         | built CLI: `npm run build`, then `node dist/bin/8cli.js` (version 0.1.2)                                  |
| Credentials  | `.local/xezar/n8n/credentials.env` – `N8N_URL`, `N8N_API_KEY`, `N8N_EMAIL`, `N8N_PASSWORD`                |
| Baseline     | a throwaway `n8nio/n8n:2.25.7` container (the old pin), probed with the same raw requests                 |
| API contract | each version's `GET /api/v1/openapi.yml`, compared path by path                                           |
| Automated    | `npm run test:e2e` – 14 files, 82 passed, 4 expected failures (the known defects); `test:e2e:macos` green |
| Date         | 2026-09-23                                                                                                |

License-gated groups (`var`, `proj`, `folder`, `sc`) were checked for the gated-error contract
only: a structured `{ "error", "code" }` on stderr, exit 1, and the message is n8n's license
refusal (not some other error).

Evidence is trimmed. IDs are from the local instance; API keys and passwords are never shown.

## Results by command

`works` – behaves as documented. `changed` – works, but n8n 2.40.5 behaves differently from
2.25.7. `broken` – does not do what the command promises.

that is n8n's own wording for a missing id (404), the same on 2.25.7.

## The n8n API gotchas in CLAUDE.md

Checked with raw requests against both versions. The e2e test "n8n PUT /workflows/{id} gotchas"
in `test/e2e/workflow.e2e.ts` now locks each rule, so a future bump shows which one moved.

| #   | Gotcha                                     | 2.40.5            | Evidence (2.40.5)                                                                                                                                                                                                                                                                                                                     |
| --- | ------------------------------------------ | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `PUT /workflows/{id}` rejects extra fields | holds             | `junk` → 400 `request/body Unrecognized key(s) in object: 'junk'`; `id` → 400 `request/body/id is read-only`. Wording changed (2.25.7: `must NOT have additional properties`)                                                                                                                                                         |
| 2   | `active` is read-only on PUT               | holds             | 400 `request/body/active is read-only`                                                                                                                                                                                                                                                                                                |
| 3   | settings only accepts `executionOrder`     | **does not hold** | n8n's own keys are accepted (`saveDataSuccessExecution`, `timezone` → 200); only unknown keys fail: 400 `request/body/settings Unrecognized key(s) in object: 'bogusKey'`. Same on 2.25.7. `settings` itself is required: 400 `request/body must have required property 'settings'` – [#42](https://github.com/qodeca/8cli/issues/42) |
| 4   | public API does not expose folders         | partly stale      | 2.40.5 lists `/api/v1/projects/{projectId}/folders` in its public API spec (also present in 2.25.7's spec). 8cli still uses the internal API; not exercised further (licensed)                                                                                                                                                        |
| 5   | execution data needs `?includeData=true`   | holds             | `exec get 1` has no `data`; `exec get 1 --data` has `data.resultData.runData`                                                                                                                                                                                                                                                         |

## What changed between 2.25.7 and 2.40.5

| Area                        | Change                                                                                                                       | Effect on 8cli                                                                                   |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Delete a published workflow | refused with 409 (was allowed)                                                                                               | `wf delete` on an active workflow fails – [#43](https://github.com/qodeca/8cli/issues/43)        |
| Unpublish                   | finishes asynchronously; a delete right after it can get a transient 409                                                     | `wf deactivate` then `wf delete` can fail once – [#43](https://github.com/qodeca/8cli/issues/43) |
| Activate / deactivate       | `POST /workflows/{id}/activate` and `/deactivate` deprecated; `/publish` and `/unpublish` added                              | still works; will break on removal – [#44](https://github.com/qodeca/8cli/issues/44)             |
| Source control              | `GET /source-control/status` and `POST /source-control/push` added to the public API                                         | the correct route for `sc status` (#39) now exists; `sc push` could be implemented               |
| Workflow object             | new fields: `activeVersionId`, `activeVersion`, `versionCounter`, `nodeGroups`, `triggerCount`                               | additive; `wf save` files carry them, `wf publish` strips them                                   |
| Validation messages         | wording of unknown-field errors; source-control licence error (401 → 403, new text)                                          | messages only; codes unchanged                                                                   |
| New public API areas        | roles, role-mapping rules, promotions, LDAP/SAML/OIDC/OTel settings, log streaming, workflow history and versions, test runs | none used by 8cli                                                                                |

## e2e coverage added

All in `test/e2e/`; the map is `test/e2e/COVERAGE.md`.

- **Real executions** (`execution.e2e.ts`): a webhook-trigger fixture produces real runs, so
  `exec list` filter semantics, `exec get` with and without `--data`, and `exec delete` happy
  paths are now covered (previously deferred).
- **Published workflows** (`workflow.e2e.ts`): delete is refused while active and succeeds after
  deactivate; publish to an active workflow reaches the live version; the PUT gotchas.
- **Gated contract** (`variable`, `project`, `folder`, `source-control`): each test now also checks
  the message is n8n's license refusal. A code-only check passed on `sc status`'s 404 and hid #39.
- **n8n refusals** (`tag`, `datatable`): duplicate names, bad column type, unknown column (and
  that nothing is half-inserted), deleted table, `--limit 250`.
- **Known defects** as `it.fails` (#39, #40, #41, #42): they pass while the defect exists and fail
  once it is fixed, so the fix must remove `.fails`.
- **Cleanup**: fixtures unpublish before delete and retry only the transient "still being
  unpublished" 409, so a failed test cannot leak an active workflow.

Each new test was run against a deliberately broken CLI and failed: without `includeData` the
`--data` test failed; without the `workflowId` filter the list test got 3 executions instead of
2; with `wf delete` unpublishing first the refusal test failed (`exit code was 0, expected 1`).

## Not exercised, and why

- **Licensed happy paths** – variables, projects, folders, source control, and `cred transfer`
  to a real project need an n8n license. Only the gated-error contract was checked, as scoped.
- **`folder delete` in e2e** – checked by hand (gated). Not added to the suite: the folder spec
  already uses n8n's 5-logins-per-minute budget (#47).
- **`auth login` against n8n** – `login` only writes the keychain; no n8n call to validate.
- **Rate-limit stall in e2e** – checked by hand on a throwaway container (6 logins in a minute).
  Not automated: it costs at least 60 s and would starve the other folder tests.
